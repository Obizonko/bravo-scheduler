# Bravo'2026 — актуальний стан (12.08.2026)

Знімок стану проєкту на момент паузи в роботі, аби швидко повернутися до контексту.

## Що це

Система планування чергувань і активностей для табору «Браво'2026»:
backend на Node/Express/MongoDB (Clean Architecture), фронтенд - ванільний
HTML/CSS/JS без білд-кроку, все загорнуто в Docker Compose.

## Що вже зроблено

- **Рушій правил** (`backend/src/services/rules/`) - буфери між змінами, вікна
  харчування, обмеження на водіїв, динамічні квоти, попередження про нічні
  години, врахування замін. Чиста функціональна логіка, працює на
  `DayContext`, що будується за 4 фіксовані запити до БД (без N+1).
- **Дворівнева PIN-автентифікація**: `ADMIN_PIN` (лід) і `SUPER_ADMIN_PIN`
  (супер-адмін, автоматично проходить перевірку ліда), заголовок
  `X-Admin-Pin`.
- **Сторінки фронтенду**:
  - `index.html` («Люди») - загальний список без входу, хто зараз де,
    керування ростером; клік на людину відкриває модалку з тижневим
    календарем чергувань (години×дні) і агендою активностей.
  - `sklad.html` / `tec.html` - справжній тижневий календар (шкала годин,
    7 днів, до 3/2 слот-колонок на день), драг для створення/розтягування
    зміни. Лише на Складі колонки підсвічуються сірим за рівнем
    навантаження з майстер-плану.
  - `vodii.html` - грід навпаки (рядок = людина, колонка = день).
  - `masterplan.html` - тижневий календар загальної програми з динамічними
    паралельними доріжками (без ліміту), рівень навантаження на активність
    (низьке/середнє/високе → 1/2/3 людини), плюс вкладка «Люди» в модалці
    редагування активності - простий перелік людей з перемикачем участі.
  - `admins.html` - призначення ролі `lead`, лише для супер-адміна.
  - `monitoring.html`, `login.html`.
- **Стабільність UI**: усі сторінки оновлюються без спінера/блимання після
  першого завантаження (тихий ре-рендер), позиція скролу в тижневих
  календарях зберігається через дію, виправлено баг застарілого
  `getBoundingClientRect()` при ресайзі подій.
- **Docker**: `Dockerfile` (multi-stage) + `docker-compose.yml`
  (mongo:7 + backend), фронтенд віддається тим самим Express-процесом
  (`GET /`) - без окремого CORS/проксі.
- **Тести**: 129 unit-тестів (`node:test`) на рушій правил і валідатори.

## План деплою (обрано: бюджетний варіант, без домену/HTTPS)

Подія коротка, безпека некритична → сервер піднімається на Hetzner Cloud
(біллінг погодинний, тому дешево для короткого заходу), доступ напряму
по IP:3000, без домену й без Caddy.

1. Створити сервер: Hetzner Cloud → New Server → Ubuntu 24.04 → **CX22**
   (~€3.79/міс, але рахується погодинно).
2. `ssh root@IP` → `curl -fsSL https://get.docker.com | sh`
3. Перенести код (git push поки заблокований - див. нижче), тому напряму:
   ```bash
   # локально, з кореня репозиторію
   tar --exclude='node_modules' --exclude='.git' --exclude='logs' --exclude='*.log' \
       -czf scheduler-deploy.tar.gz .
   scp scheduler-deploy.tar.gz root@IP:/root/
   ssh root@IP
   mkdir -p /opt/scheduler
   tar -xzf /root/scheduler-deploy.tar.gz -C /opt/scheduler
   ```
4. На сервері створити `/opt/scheduler/.env` з тими самими значеннями, що
   вище (`CORS_ORIGIN=*` можна лишити, домену немає).
5. `cd /opt/scheduler && docker compose up -d --build`
6. `ufw allow OpenSSH && ufw allow 3000/tcp && ufw --force enable`
7. Посилання для всіх: `http://IP:3000`
8. **Після події - видалити сервер** у консолі Hetzner, щоб не капала оплата.

`deploy/Caddyfile` уже в репозиторії - готовий на майбутнє, якщо колись
захочеться додати домен + автоматичний HTTPS (просто зараз пропущено).

## Відкриті питання / незавершене

- **git push заблокований**: `origin` = `https://github.com/Oleh3542/scheduler.git`,
  push видає `403: Permission to Oleh3542/scheduler.git denied to Obizonko`
  - у Windows Git Credential Manager закешований акаунт `Obizonko`, який не
    має прав запису в цей репозиторій. Весь код цієї сесії закомічено
    локально (гілка `master`, комміт `5324a1c` + попередні 7), **push не
    пройшов**. Варіанти вирішення:
    1. Якщо `Oleh3542` - основний акаунт власника: очистити закешовані
       git-креденшли в Windows Credential Manager (шукати записи
       `git:https://github.com`) і зробити push заново - GCM перепитає
       логін, увійти під `Oleh3542`.
    2. Якщо `Obizonko` - робочий акаунт: попросити власника `Oleh3542`
       додати `Obizonko` як collaborator у налаштуваннях репозиторію на
       GitHub (Settings → Collaborators).
    3. Форкнути репозиторій під `Obizonko` і запушити туди, далі відкрити
       Pull Request в `Oleh3542/scheduler`.
- **Rate-limit на PIN**: `/api/v1/auth/pin` без обмеження спроб - не
  критично для короткої події, але якщо колись піде публічний тривалий
  доступ - варто додати `express-rate-limit`.
- **Бекап MongoDB**: дані живуть лише в Docker volume на тому сервері, де
  піднято compose - на короткій події це прийнятний ризик, але варто
  пам'ятати.
